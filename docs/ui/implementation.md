# 장비 근거 데스크 UI

공개 카탈로그의 장비 원문을 찾고, 실제 실행한 조회 기록을 비교하는 데스크입니다. 장비 예약, 방문 이용 권한, 현재 교정 상태, 제조·시험 적합성을 판단하지 않습니다.

## 화면과 원문

- 실험 A는 고정된 8행 원문 집합에서 원문 조회, RAG, All-context를 구분합니다. RAG는 선택된 상위 원문을, All-context는 공유범위 내 전체 원문을 사용합니다. All-context는 **캐시 재사용 검증 안 됨**으로 표시합니다.
- 실험 B의 50행 미리보기는 검색 전용입니다. UI에서 모델 방식을 비활성화하고 원문 조회만 선택합니다.
- 같은 질문·공유범위·스냅샷의 실제 기록만 나란히 유지합니다. 각 카드에 실제 제공 문서 ID와 독립적인 실행 상태를 표시하며, 실행하지 않은 방식은 미실행으로 남습니다.
- 장비 표는 한국어·영어 원문 이름, 모델, 제작사, 공유범위 표기를 보존합니다. 문서 ID는 스냅샷 자료 기록 ID이며 물리 장비 ID가 아닙니다.
- 이름이 지정된 native dialog에서 모든 원문 필드, 카탈로그 날짜, 카탈로그·행 해시를 확인합니다. 인용 버튼은 서버가 검증한 인용과 행 해시·코드포인트 범위가 일치할 때만 원문을 강조합니다.
- 모델의 답변 상태, 정보 부족, 제공기관 확인 질문, 수량 유형·단위·조건 제안을 분리합니다. 원문 인용 일치는 의미적 함의나 실제 장비 성능의 검증을 뜻하지 않습니다. 표기 차이와 조건 미확정은 물리적 충돌의 입증으로 표시하지 않습니다.

## 요청·복구

첫 화면은 health와 catalog GET만 실행합니다. 자동 질의·모델 호출은 없습니다. 질의 POST는 사용자 제출 한 번에 한 번 실행하며 busy 중 중복 제출을 막습니다. 새로 열기와 마지막 기록 복구는 저장 기록 GET만 실행합니다. 기록 ID는 세션 범위 저장소에 보관하며 인증 토큰은 사용하지 않습니다.

GET의 15초, POST의 190초 응답 제한을 넘기면 상태를 명시하고 자동 재전송하지 않습니다. 페이지를 떠나면 브라우저 요청만 취소되며 서버 측 작업 완료를 보장하지 않습니다. 기록은 서버 메모리에 있으므로 재시작·기록 보관 한도에 따라 없어질 수 있습니다. 누락된 기록은 사용자에게 안내하고 모델 요청을 다시 실행하지 않습니다.

외부 텍스트는 textContent와 DOM 생성으로 표시합니다. 원문 링크는 서버의 공공데이터포털 HTTPS 출처만 연결합니다. 모달 내부 오류는 모달 안의 assertive live 영역에서도 표시합니다. Escape 또는 돌아가기 버튼은 원래 원문·인용 버튼으로 포커스를 복귀합니다. 인용 이동은 항상 auto이므로 reduced-motion에서도 애니메이션을 사용하지 않습니다.

## CPU 검증과 실제 캡처

첫 7장의 CPU 캡처는 모델 비활성 서버의 실제 화면입니다. RAG·All-context 두 기록도 health의 model_enabled=false를 각각 확인한 뒤 생성한 **모델 사용 불가 CPU 기준선**입니다. 이 CPU 캡처에는 실제 모델 답변 또는 GPU 성능 측정이 없습니다.

[검사 기록](captures/browser-check.json)을 통해 실제 요청과 모의 응답을 구분할 수 있습니다. 실제 Chrome 브라우저 검사 17개 항목, CDP 전송 단위검사 3개, Node 구문 검사를 수행했습니다. 텍스트 대비는 실제 렌더링 색상과 합성 배경을 계산했으며 최솟값은 5.0694:1입니다. 비활성 컨트롤은 대비 계산에서 제외했습니다.

## 남은 검증 범위

본문·장비 행·사실은 14px 이상, 질문·원문은 16px이며 메타데이터는 12–13px입니다. 390px 화면과 모바일 작업 탭, 720px 재배치를 검사했습니다. 720px 검사는 1440px에서 200% 확대했을 때의 뷰포트 폭에 해당하지만 브라우저 자체 확대 조작은 수행하지 않았습니다. 완전한 보조기술·키보드·접근성 감사와 다양한 질의·실패에 대한 실제 모델 UI 검증은 아직 수행하지 않았습니다. 아래 실제 모델 화면·영상은 D1 한 건에 한정됩니다. 평가 정답 자료는 UI와 검사에서 읽지 않습니다.

## 문구 규칙 보류 상태 후속 검사

서버가 현재 예약·교정·방문 상태 또는 물리 장비 동일성 확인 요청을 문구 규칙으로 **감지한** 경우, `policy_abstained`를 **공개 목록으로 확인 불가 · 모델 미호출**로 표시합니다. 보류 이유와 제공기관 확인 질문을 직접 보여주고, 검색 후보가 상태·동일성의 증거가 아님을 설명합니다. 이 규칙이 모든 표현을 탐지하거나 의미 검증을 완료했다는 뜻은 아닙니다.

별도 모델 비활성 CPU 서버에서 현재 상태 질문과 동일 물리 장비 질문을 각각 RAG·All-context로 실행했습니다. 네 실제 응답의 rule_gate.model_called=false, 빈 facts, 빈 model_metrics, 미실행 인용·의미 검사를 확인했습니다. [후속 검사 기록](policy-followup/policy-check.json)은 실제 보류 응답 네 건과 390px 재배치 검사, 총 5개 항목을 기록합니다. 기존 17개 브라우저 검사도 별도 임시 출력 위치에서 다시 통과했으며 이전 캡처는 덮어쓰지 않았습니다. 단위검사는 기존 CDP 전송 3개와 보류 검사 근거를 확인하는 2개, 총 5개가 통과했습니다. Node 구문 검사도 통과했습니다. 이 후속 단계의 모델·GPU 요청은 0건입니다.

## 실제 모델 D1 한 건의 UI 캡처

CPU 기준선과 별도로, 질문 **N9030A에 적힌 최대 반송파 주파수는 얼마인가?**를 RAG로 한 번 제출했습니다. 실제 응답은 `model_validated_citations_only`, 기록 ID는 `fc38c5e16dba14e9f84deb19`입니다. 화면의 44GHz 제안과 인용 범위는 원문 `Maximum 44GHz Carrier Frequency`와 일치했습니다. `semantic_entailment_verified=false`를 유지하며, 이 한 건을 동결 평가·질의 품질·장비 적합성 검증으로 취급하지 않습니다.
